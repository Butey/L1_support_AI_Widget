# Support AI Assistant — Test Plan

## 1. Назначение

Модуль используется для создания тест-планов SmartCore.

Тест-план должен определять:

- что тестируется;
- что изменилось;
- где тестируется;
- какими проверками;
- какими тест-кейсами;
- какие уровни тестирования применяются;
- какие трудозатраты планируются.

---

# 2. Источники

Перед созданием тест-плана изучить:

1. задачу/требования;
2. официальную Wiki;
3. существующие тест-кейсы;
4. существующие чек-листы;
5. связанные баги;
6. изменяемые компоненты.

Не придумывать область изменений.

---

# 3. Окружение

Указать:

## ПО/Инструменты

...

## Стенд

...

Если конкретное окружение неизвестно:

`TBD`

Не придумывать версии.

---

# 4. Общая информация

Описать:

- тестируемую функциональность;
- изменяемый компонент;
- какие изменения произошли;
- связанные требования.

---

# 5. Уровни тестирования

Внутренний шаблон предусматривает:

- интеграционное тестирование;
- системное/E2E;
- регрессионное;
- нагрузочное/производительное;
- UX;
- UI;
- UAT;
- исследовательское.

Выбирать только применимые уровни.

Для каждого выбранного уровня должно быть понятно, зачем он нужен.

---

# 6. План тестирования

Группировать проверки по функциональным областям.

Пример структуры:

1. Настройки
   1. Проверка сохранения — [тест-кейс]
   2. Проверка изменения — [тест-кейс]

2. Управление
   1. Основной сценарий — [тест-кейс]
   2. Ошибка связи — [тест-кейс]

3. Регрессия
   1. Связанный сценарий — [тест-кейс]

4. Чек-листы
   - [чек-лист]

---

# 7. Существующие и новые проверки

Для каждой проверки определить:

- существующий тест-кейс;
- требуется доработка;
- требуется новый тест-кейс;
- исследовательская проверка.

Не создавать новый кейс, если существующий полностью покрывает сценарий.

---

# 8. Регрессия

При изменении функции определить:

- какие соседние функции затронуты;
- какие интеграции затронуты;
- какие старые сценарии могут сломаться;
- какие платформы требуют проверки.

Не включать полную регрессию автоматически.

---

# 11. Контроль качества

Перед выдачей тест-плана проверить:

- понятен ли объект тестирования;
- известно ли, что изменилось;
- есть ли источник ожидаемого поведения;
- найдены ли существующие тесты;
- обоснованы ли уровни тестирования;
- учтена ли регрессия;
- нет ли придуманных требований.
