# Support AI Assistant — Bug Report

## 1. Назначение

Модуль определяет правила формирования багрепортов SmartCore.

Багрепорт фиксирует наблюдаемое несоответствие между ожидаемым и фактическим поведением.

Он не должен использоваться для фиксации неподтверждённых ожиданий.

---

# 2. Перед созданием багрепорта

Проверить:

1. Есть ли источник ожидаемого поведения?
2. Воспроизводится ли проблема?
3. Известно ли окружение?
4. Известны ли шаги?
5. Можно ли описать фактический результат?
6. Есть ли workaround?

Если ОР не подтверждён:

> Требуется уточнить ожидаемое поведение до подтверждения бага.

---

# 3. Ожидаемый результат

ОР должен основываться на:

- требованиях;
- официальной Wiki;
- подтверждённой спецификации;
- согласованном поведении.

Не придумывать ОР из личного ожидания пользователя.

# 5. Предусловия

Описать состояние системы до воспроизведения.

Предусловия должны позволить другому тестировщику подготовить аналогичное окружение.

---

# 6. Шаги воспроизведения

Шаги:

- последовательные;
- минимально достаточные;
- воспроизводимые;
- без лишних действий.

Один шаг — одно действие.

---

# 7. Ожидаемый результат

Описать конкретное наблюдаемое поведение.

Плохо:

> Всё работает корректно.

Хорошо:

> После сохранения значение отображается в поле и сохраняется после повторного открытия проекта.

---

# 8. Фактический результат

Описать:

- что произошло;
- чем отличается от ОР;
- сообщение об ошибке;
- визуальный результат;
- необходимые логи.

Не добавлять предполагаемую причину как факт.

---

# 9. Последствия

Во внутреннем шаблоне предусмотрено описание последствий бага.

Например:

- блокирующие;
- незначительные;
- вызывают цепочку последствий.

Описывать конкретное влияние.

Не назначать severity только по эмоциональности обращения.

---

# 10. Обходной путь

Указать:

`Есть`

или:

`Нет`

Если есть — описать последовательность действий.

Workaround не является окончательным исправлением.

---

# 11. Доказательства

При необходимости приложить:

- скриншоты;
- видео;
- логи;
- проекты;
- дампы;
- сетевые трассировки;
- другие диагностические данные.

Не включать секреты и учётные данные в открытый текст.

# 13. Отличие от аварии

Багрепорт — тестовый/разработческий артефакт.

Категория «Авария» — процесс ТП.

Наличие багрепорта само по себе не означает, что клиентское обращение должно быть классифицировано как «Баг» или «Авария».

Для классификации использовать:

`support-classification.md`

---

# 14. Запреты

Не:

- придумывать причину дефекта;
- придумывать ОР;
- путать предположение пользователя со спецификацией;
- использовать «работает некорректно» вместо ФР;
- скрывать информацию об окружении;
- смешивать workaround и фикс.
